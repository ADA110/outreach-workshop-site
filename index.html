    Overview

    What you're building today

    You'll build a small team of AI agents in Claude Code, then use it to write a real cold email. The email is the project. The agents are what you're here to learn.

    Two things about how this works

    Several steps from here have three tabs: Beginner, Intermediate, and Advanced. You picked one at sign-in, and you can flip any step to a different one. Nobody is expected to finish in the session, and your progress is saved, so carrying on afterwards is the normal outcome rather than a failure.

    The team

    Your main Claude Code session, the chat you type into, runs the team. It never researches or writes the email itself. It hands each job to an agent built for exactly that job. Claude Code calls these subagents, and you will see that word in the prompts.

    How the agents hand off work

    The agents never talk to each other. Each one does its job, then writes a Markdown (.md) file: a note for the next agent to pick up. That note is the handoff.

    1. researcher writes 01-brief.mdThe brief: 3 to 5 dated facts about the company

      The Writer reads the brief

    2. writer writes 02-draft.mdThe draft: a first version of the email

      The Editor reads the draft, checking it against the brief

    3. editor writes 03-final.mdThe final email, cut down and in your voice

      You read the final, and from Step 08 so does the Recruiter

    4. recruiter writes 04-review.mdThe review: a score out of 10 and what to fix

      A score under 8 sends it back to the Writer for one more pass

    Every note lands in runs/<company>/. After a run, open them in order and you'll see exactly what each agent was handed and what it passed on.

    Why build it this way

    Cold outreach makes a good first agent project. The job splits into clear steps, each step needs different information, and you can judge the result yourself.

    One job per agent

    Each agent gets a short, focused prompt and only the tools that job needs. When something goes wrong, you know whose prompt to fix.

    Handoffs you can read

    Every step writes a file. Open any of them and you'll see exactly what the next agent was given.

    You stay in charge

    The agents only draft. You review every email and send it yourself.

    House rules

    • AI drafts, you send. Claude only ever writes a draft. You review every email and send it yourself, because you own the words in it.
    • Every claim traces to the brief. If a fact isn't in 01-brief.md, it doesn't belong in the email.
    • Your main Claude Code session never edits the email. That's the session you type into, and it runs the team as the manager. If the email needs changes, it goes back to the Editor.

    Why that allow list is shaped like that

    Every rule in it is an Edit(...), and none is a Write(...), although the agents create files rather than editing them. That is deliberate: Claude Code checks file permissions against Edit and Read rules only, and a Write(...) path rule is accepted, never consulted, and warned about at startup. Edit(runs/**) is what lets an agent create 01-brief.md. The Bash entries are there because making a run folder and listing it are the two shell commands this pipeline needs.

    Question to sit with

    Your rulebook and an agent prompt disagreed. Which won, and why can't you lean on that?

    Usually the more specific instruction, and the one closest to the work. An agent's own prompt sits directly in its instructions, so a concrete rule there tends to beat a general one in the rulebook. That is a tendency rather than a guarantee: the model is reconciling two sets of instructions, and the same conflict can resolve differently on another run.

    So never build a pipeline that depends on a conflict landing your way. Keep the rulebook for what is true everywhere, keep agent prompts for the job at hand, and when you find a contradiction, remove it rather than deciding which should rank higher.

    Question to sit with

    Your Writer invented something anyway. Which part of your prompt allowed it?

    Usually two things together. A prompt that says what to produce ("a compelling opening hook") without saying what to do when the material isn't there, and a prohibition phrased only as a ban ("never invent facts"). Told to produce a hook and given nothing to build one from, the model resolves the conflict by inventing.

    The fix is an instruction for the empty case, not a stronger ban: if the brief is thin, write a shorter email, or ask a question instead of making a claim. Give the failure case somewhere to go. Taking the web tools away closes the other route, so the Writer cannot quietly go and find a fact of its own.

    Question to sit with

    The Writer has no web search. Why would you deliberately take a tool away from an agent?

    So the brief is the only place facts can come from. If the Writer could search, it could pull in something the Researcher never checked, and the rule that every claim traces to the brief would be impossible to enforce.

    Fewer tools makes an agent predictable. When a fact shows up in the email, you know exactly where it came from. It also keeps the jobs separate: research is the Researcher's job, and an agent doing both hides which step a mistake came from.

    Step 04

    Restart, then check the team loaded

    Quit Claude completely, then open it again. This step isn't optional, and it is the one step people get wrong.

    Quit the application, not the window

    Closing the window leaves Claude running behind it. So does closing the session. Neither restarts anything, so your agents stay unloaded and nothing warns you. The application itself has to stop and start again.

    On a Mac: press Cmd+Q, or go to the Claude menu at the top left of the screen and choose Quit Claude. The red button in the corner of the window only closes the window. To be sure it worked, look at the Dock: Claude should be gone, or have no dot under it.

    On Windows: close the window, then look in the system tray, the small icons next to the clock, and click the arrow to show hidden ones. If Claude is there, right-click it and choose Quit or Exit. To be sure it worked, check that Claude is gone from both the taskbar and the tray.

    Then open Claude again and click your agents-outreach-team session in the sidebar to pick up where you left off.

    Nothing you have built lives in the chat. Every file is on disk, so quitting loses none of it, and your conversation is still there when you come back.

    Working in a terminal instead? Type /exit, then run claude again in the same folder.

    The check below is how you find out whether it worked. Do it before you move on.

    Why the restart is required

    Claude Code watches .claude/agents/ and picks up new or edited agents within seconds. The catch: it only watches folders that already existed when the session started. You created that folder a minute ago, inside a session that began before it existed, so nothing is watching it yet. Nothing will warn you either. Your main session will simply have no agents to hand work to.

    Once you're back in, ask Claude:

    Without opening any files, list the subagents you can delegate to right now. For each one, give its description and the exact tools it is allowed to use.

    You will see more than three. Claude Code ships with its own helpers, with names like general-purpose, Explore and Plan, and those have always been there. What you are checking is that researcher, writer and editor are in the list too, and that the tools are right: the Researcher has web search and web fetch on top of read and write, and the other two have read and write only. The web tools are the tell. The tool lists are the point. They live inside your agent files and nowhere else, so a session that loaded nothing cannot answer without opening them.

    Why "without opening any files" is doing the work

    CLAUDE.md names all three agents and is already open, so asking for names alone gets you the right answer whether or not a single agent loaded. The agent files are on disk either way too, so a session that can read them can report anything in them. The only thing that separates a loaded session from an unloaded one is what it can tell you without looking.

    If you wrote your own agent files

    Then the tools are whatever you gave them. If you left tools out, that agent reports every tool it could have, which is the file doing what it says rather than a failed restart. What matters is that all three names are there without Claude opening anything.

    If you wrote your own agent files

    Then the tools are whatever you gave them, and an agent with no tools line reports every tool it could have. What matters is that all three names are there without Claude opening anything. If you already restarted for the thin-brief test one step ago, you do not need to restart again: just run the check.

    Question to sit with

    If you left these files empty, the pipeline would still produce an email. What exactly would be wrong with it?

    It would be all about the company and say nothing real about you. The Writer is only allowed to say things about you that are in background.md, so with nothing there its "why me" line goes vague because it has nothing true to say.     Your judge scored B higher than A. Give two reasons that might be wrong.

    Too few samples. With two runs per version, the spread inside one version is often as wide as the gap between versions. The same prompt run twice gives different emails, and that noise is easy to read as an improvement.
